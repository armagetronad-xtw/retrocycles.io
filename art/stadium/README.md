# Stadium assets (Blender)

The stadium around the arena (`src/tron/gStadium.cpp`, `STADIUM` / `SCENE_STADIUM`) is built
from pieces modelled and lit here. Everything is generated by script; the `.blend` files are
saved for looking at and hand edits, but the script is the source of truth.

| file | what |
|---|---|
| `build_stadium.py` | builds the pieces in Blender, bakes their light, renders the crowd, exports |
| `pack_textures.py` | turns the rendered crowd atlas into the shipped palette PNG (Pillow) |
| `Dockerfile` | headless Blender 4.2 LTS (`aa-blender`) |
| `stadium.blend` | the pieces and the bake setup as the script left them |
| `crowd.blend` | the last crowd row the script rendered, with its lights and camera |
| `build/` | intermediate renders (git-ignored) |

Outputs (shipped, preloaded into the browser build's data):
`models/stadium/stand.stm` (one 24 unit stand module), `models/stadium/flood.stm` (a floodlight
bank), `models/stadium/board.stm` (a scoreboard housing), `textures/stadium/crowd.png`.

## Running it

```
docker build -t aa-blender art/stadium                      # once (downloads Blender, ~350 MB)
docker run --rm -v "$REPO:/repo" aa-blender --python /repo/art/stadium/build_stadium.py -- /repo
python3 art/stadium/pack_textures.py "$REPO"                 # host Python with Pillow
```
Cycles on the CPU, 48 samples (`-e STADIUM_SAMPLES=16` for a quick look,
`-e STADIUM_SKIP_CROWD=1` to leave the crowd atlas alone). download.blender.org refuses scripted
downloads, so the Dockerfile uses a mirror (`BLENDER_MIRROR`).

## What the script makes

Space: x along the stand, y outwards from the arena's rim, z up, in *bowl units*; the game
scales them to the arena (`unit = max(half the larger side, 60) / 125 * STADIUM_SIZE` grid
units) and bends the straight module round the bowl's rounded corners.

- **Stand module** (`LENGTH` 24): podium wall with a cyan LED ribbon; lower tier of 14 stepped
  rows (riser + tread each), concourse with a vomitory tunnel (warm lit back) and lamps, upper tier
  of 16 rows, fascia with a white LED ribbon, top walkway, back wall, a cantilever roof with two
  truss girders and a white LED edge; a stairway at the start of every module with step lights.
  Every row carries a *crowd card*: one quad standing on the tread, textured with a strip of the
  crowd atlas, so each row of spectators sits at its own depth.
- **Lighting**: Cycles bakes direct + indirect diffuse light into a colour attribute (night sky,
  a large soft source over the arena, this side's floodlights aiming at the floor whose bounce
  lights the stands, warm concourse light); neighbouring copies of the module and the floor plane
  take part for occlusion. The export multiplies each material's albedo into the baked light and
  scales the bright end (97th percentile) to 0.55, so the stands stay dark.
- **Crowd atlas** (1024x512, 8 rows of 64 px): low-poly seated spectators (torso, head, legs,
  seat back), muted shirts, about one in eight with a raised phone light, a few holding a scarf in
  a team colour, rendered orthographically from the arena side with a cool key and a warm rim,
  transparent background.
- **Floodlight bank** and **scoreboard housing**: small rigid pieces (not baked); the screen
  is a `@board` part the game fills with its dot-matrix text.

## The .stm format

Little endian: `"STM1"`, `u32` version 1, `f32` module length, `u32` part count; per part: `u8`
blend (0 opaque, 1 alpha tested, 2 additive), 3 pad bytes, `f32` glow (its share of the bloom),
`char[64]` texture (`""` none, `"@dash"`, `"@panel"`, `"@glow"`, `"@board"` = one the game
generates, else a data path), `u32` vertex count, `u32` index count, vertices (`f32` x y z u v,
`u8` r g b a, sRGB), `u32` triangle indices. Parts group triangles by material.
