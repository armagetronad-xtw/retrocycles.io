eight.webm, eight.mp4, eight.png: the connecting screen's cycle (src/components/Connecting.tsx)

What it is: the game's own renderer (this repository's wasm client) drawing one
cycle with its wall running a figure 8 of two crossing squares, through the attract scene's
replay (src/tron/gScene.cpp), on black (SCENE_STADIUM 0, SCENE_DOF 0, SCENE_FLOOR_DETAIL 0,
SCENE_FLOOR_REFLECT 0, SCENE_RIM 0). It is rendered
white; the page multiplies it by the player's colour (COLOR_*_1), so the cycle is always
the player's own. The models and textures are the game's (GPL, see /licenses/).

How it was made (web/page/tools/connect-eight/):
 1. node make_header.js src/tron/gSceneReplayData.h   (a THROWAWAY replay: one white cycle,
    S = 6 log units a side, 18 log units/s, one lap = 2.67 s, wall 27 game units). Keep a
    copy of the real header first and put it back after step 2; the throwaway is never
    committed.
 2. delete web/wasm/build/client_opt/tron/gScene.o (the Makefile does not track the header),
    build the optimised client; copy client_opt.*,
    aa_api.js and client.html out and serve them (node serve.js <dir>, port 5199).
 3. client.html?build=opt at 720x720 with the canvas full-window; then
      SCENE_REPLAY 1, SCENE_STADIUM 0, SCENE_DOF 0, SCENE_FLOOR_DETAIL 0, SCENE_FLOOR_REFLECT 0,
      SCENE_RIM 0, SCENE_REPLAY_X/Y 0.5,
      SCENE_REPLAY_SPEED 0.1, SCENE_REPLAY_CAMERA_MODE 0, _DIR -45, _Z 25, _PITCH -1.3,
      _FOV 44, _X/_Y = the camera 21.2 units behind the centre along -DIR, / 125;
      aa.scene(1); wait 4 s; screenshot as fast as possible for 29 s into frames/<ms>.png.
 4. node assemble.js <dir> 26660   (one lap of the tenth-speed replay, 80 frames at 30 fps)
 5. ffmpeg -framerate 30 -i out/f%03d.png
      -vf "crop=600:600:60:70,eq=gamma=1.5:contrast=1.15,scale=480:480:flags=lanczos,format=yuv420p"
      -c:v libvpx-vp9 -b:v 0 -crf 32 eight.webm   (and libx264 -crf 22 eight.mp4; frame 27 as eight.png)
 6. rebuild the client from the real header (delete gScene.o again).
